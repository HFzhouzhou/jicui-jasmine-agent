## 2. 测试如何判定

- **固定资料和答案**：先固定资料、问题和预期关键事实，再跑基线。对话集 18 份虚构资料，检索集 22 份虚构资料（包含草稿和归档），菜单使用 4 个虚构商品。没有读取或修改真实运行数据库。
- **知识完整性**：每条预设事实要出现在回答中，引用要包含指定资料；引用摘录必须确实存在于当前已发布正文。来源编号、页码与版本由服务端校验。
- **不乱答**：天气、外部行情、当前时间、未知电话/许可证/生产日期/检测数据、要求“猜一个”、未发布暗号等均单列测试。安全测试接受明确资料不足或固定澄清，不接受任意无引用生成文本。最终 6/6 天气问题没有编造天气。
- **点单不回退**：验证商品存在且可选、单价与加料价格正确、总价不超过预算、糖冰合法、过敏限制保留、售罄不返回。知识词语不是购买指令；明确个人忌口仍然持续有效。
- **失误不藏起来**：请求报错、生成/引用核验降级都计为失败；中间 40/43、41/43 的版本及一次分类格式失败保留在原始报告，不删除或挑最好的一轮拼分数。最终记录是一轮完整的最终代码运行。

自动判分使用固定事实正则、来源标识和商品约束，不能覆盖一切语言含义。新增的模型证据核验是运行时防护，**不是用模型自己的评分替代测试集标准答案**。

## 3. 根据结果修复了什么

1. **中文检索漏词**：补充 ICU 分词遗漏的业务词和相邻名词片段，保留“茉莉花＋香”中的“花香”；保留问句前面的主题背景。原问题、独立改写分别检索后融合，避免把长历史直接混成一条查询。
2. **错误前提与冲突**：遇到“某个样品的编号是不是 AB-999”这类确认问句，保留精确编号查询，同时查询独立主体来寻找纠正证据；只有未知编号时不泛化乱找。近似但数字或否定不同的资料不再被去重丢掉。
3. **引用真实、结论错误**：先检查引文确实存在，再单独验证每条结论是否被引文支持、是否回答当前对象。时间和计量数字按完整 token 核对，避免 `10元` 错误匹配 `0元`；支持常见同量纲单位换算。缺失、重复、失败判定不放行生成事实，生成失败不把未核验片段当回答。
4. **知识串进点单偏好**：“无糖是什么意思”“牛奶过敏是什么”不会变成用户的甜度或个人过敏情况。真实的“我牛奶过敏”仍保留。混合请求同条返回引用和商品卡。
5. **聊天中商品上下文丢失**：知识、菜单事实和澄清保留当前茶单；新推荐包含无匹配结果才替换。配置独立持久化，刷新恢复；提交时携带当前选中商品的 ID，价格由服务器重新读取。
6. **续聊边界**：只有纯粹“再推荐一杯、其他不变”才允许在模型空 ID 时重新筛选；明确指定不存在的商品不会被其他茶替代。“不额外加料”不再误当加料要求。无菜单语境的行情问题不会被“多少钱”误导成商品报价。

## 5. 限制与后续评估

检索开发过程中，激进阈值候选在最初留出的 18 道可答题上由 13/18 降到 9/18，因此被淘汰。恢复保守策略后，原留出部分为 16/18；由于已经揭盲，**后续 72 题只能称固定回归，不能声称独立留出验证**。没有更改这些题的标注来提高分数。

最终词法层仍遗漏 2/54 个预期答案（英文积分兑换、长背景失物问句），存在 4/18 个词法误召回。模型核验能降低错误回答风险，但仍可能误拒答或漏判。生产效果还取决于资料正确性、是否发布、解析完整程度、模型波动；目前不能保证任何提问永远正确。建议下一阶段由品牌方用真实且核准的资料独立编写一批未见问题，并保存人工审核答案，再作为发布门槛。
