# RAG 知识库维护指南

本模块把文件解析、资料发布、检索、回答和引用分开。上传完成只代表已解析，不代表内容正确或已发布。管理员应核对解析结果与来源，再让资料参与顾客问答。

## 使用流程

1. 进入管理后台的「知识库」，选择或拖入 PDF、DOCX、DOC、TXT、MD、CSV。每批最多 10 份，队列逐份显示完成或错误，可重试失败项。
2. 选择书架中的资料，预览片段、页码或章节，检查乱码、缺页、表格、扫描图片提示，补充标题与来源。原文件仅管理员可下载。
3. 核准后发布。草稿、归档资料不会进入顾客问答，也不会被顾客接口下载。
4. 在「检索试验台」输入顾客可能问的问题，检查命中片段与出处。默认只查已发布内容，可主动包含草稿，或限定某份文档。
5. 到随心配页面提问。回答使用编号引用，展开「查看回答依据」可见原文摘录、文件标题、页码和来源。
6. 资料变更时可修订正文。修改已发布正文会自动撤回成草稿，核准后再发布。归档可恢复，不会物理删除原文件。

保存使用乐观锁，其他窗口已改过的资料不能被旧页面覆盖。遇到版本冲突时，界面保留未提交的编辑，载入新版后再核对。已有旧知识条目会自动迁移；在新后台撤回或修改后，不会在重启时被未改变的旧条目覆盖。

## 架构

```text
管理员上传（认证、限额）
  → 独立解析子进程（签名校验、硬超时、取消、进程组清理）
  → 标准正文 + 页码/章节 + 解析提示
  → 按段落/句子分块、同节重叠
  → SQLite 文档/原文件/片段/FTS5 索引（默认草稿）
  → 管理员发布

用户问题 + 必要的前文
  → DeepSeek 意图解析与独立问题改写
  → 原问题与独立改写分别进行中文 FTS5 / BM25 检索，RRF 合并（可选向量只用于一路）
  → 相关性筛选、相似段去重、跨文档多样性选择
  → 最多 6 个片段交给 DeepSeek 生成带原文证据的回答
  → 服务端核对引用属于本次检索、原文包含摘录
  → 独立模型步骤核对每条结论是否受证据支持、是否回答当前问题
  → 服务端补查时间/计量数字、重复判定，并再次确认资料仍已发布
  → 回答 + 引用；没有足够依据时明确告知
```

模型不会拿到整份知识库。资料、文件名、出处和聊天历史均作为数据处理，不能覆盖系统指令。引用校验验证来源、摘录和当前版本，再用第二次有界模型调用核验结论与证据的语义关系，并检查部分结构化数字。缺失、重复、失败的核验不放行生成结论。格式错误仅修复一次；生成或核验服务异常会说明尚未完成核验，不返回未核验结论，也不把未经相关性核验的片段当回答。仅明确的规则预览模式保留原文摘录。**模型核验仍不等于数学上证明每个概括都准确**；重要配方、数字、表格和冲突资料仍应由管理员核准。文档不能覆盖菜单数据库里的价格、实时库存、过敏原及可选规格规则。

### 默认检索

- 使用 Node.js 24 的 `Intl.Segmenter` 分词，结合中文字双元组，减轻中文没有空格及部分词形不一致的影响。
- SQLite FTS5 持久化索引与 BM25 候选召回，综合正文覆盖、标题、词组、领域同义词进行排序。所有 MATCH 查询均由转义后的索引词生成。
- 泛化的「茶」「茉莉」不能单独支撑无关问题。低相关性段落被过滤；阈值是启发式检索分数，不是事实可信概率。
- 分段优先保持页、章节、段落和句子，通常约 850 字，每段上限约 950 字；仅同一来源段落保留约 120 字重叠。原始规范正文另存，不从重叠片段反拼。
- 去重与多样性重排控制重复片段数量，同一文档最多保留 3 个候选。跨文档仅剔除完整相同正文，不能因为措辞接近就丢掉不同数字或相反表述，否则会隐藏资料冲突。
- 原问题和模型改写分别检索后融合，避免把长历史与当前问题简单拼接造成稀释。短追问可补入上一条真实用户问题，排除商品卡配置记录；不把上一轮助手的生成事实当新证据。

### 可选向量混合检索

未配置向量服务时，本地全文检索即可工作，不会偷偷把文件发送到其他提供方。需要更强的语义召回时，在私有 `.env` 配置支持 `/embeddings` 的服务：

```dotenv
RAG_EMBEDDING_BASE_URL=https://your-authorized-provider.example/v1
RAG_EMBEDDING_MODEL=your-embedding-model
RAG_EMBEDDING_API_KEY=
RAG_EMBEDDING_TIMEOUT_MS=8000
```

以上是配置格式占位，不能直接当真实地址使用。向量服务独立于 DeepSeek 聊天服务；只填写 `DEEPSEEK_API_KEY` 不会自动开启向量功能。本地服务允许回环 HTTP，远程服务必须 HTTPS。配置后重启应用。

- 缓存按提供方、模型、片段标题和正文哈希校验，资料修订立即使旧缓存失效。未知维度、异常数值、超时或错误响应回退到本地检索。
- 一次请求最多补齐 32 个片段，单次混合检索总限时约 8 秒；逐步建立索引，控制小服务器的内存和外部调用成本。
- 向量与词法排名通过 RRF 融合，再执行多样性去重。向量相似度阈值需要结合实际语料和模型调优。
- 后台展示当前检索范围内实际向量覆盖数。覆盖未满时，不代表所有文档都已具备语义召回；未索引部分仍可全文检索。
- 管理员主动包含草稿检索且已配置向量服务时，范围内的草稿片段可能发送给该服务。只配置已获授权的提供方；默认关闭。

## 解析能力与限制

| 格式 | 能力与边界 |
| --- | --- |
| PDF | PDF.js 按页提取文字；保留物理页号。加密、损坏、空文档及超限会明确报错。复杂多栏、字体编码、表格顺序需要人工核对。 |
| DOCX / DOC | Word Extractor 提取段落、表格文本及可用页眉脚注等；不执行宏、不打开外部链接。Word 自动分页依赖排版环境，因此不伪造页码。 |
| TXT / MD | 支持常见 UTF-8、UTF-16 和 GB18030 中文文本；Markdown 标题可成为章节。不会执行 HTML、脚本或链接。 |
| CSV | 解析引号、逗号和跨行字段为可读文本；不执行单元格公式。 |
| 扫描 PDF | 可选本地 OCR，须安装 Poppler、Tesseract 与 `chi_sim`、`eng`。未识别页会给出错误或具体缺页提示，不静默丢掉整页。 |

OCR 安装指令见 README。Dockerfile 包含这些运行依赖；原生部署按需安装。Word 内嵌图片、混合页面中的图片文字、手写字、复杂表格和图表无法保证完整识别，解析提示会说明相应限制。扫描 PDF 中文本极少的页才进入 OCR，不能把「有文字层」等同于图片里的所有字均已识别。

独立解析进程的 Node 堆上限 256 MB，180 秒超时，停止应用或取消请求会终止解析及其子进程组。OCR 工具还会使用原生内存；单应用一次只处理一个上传解析任务，适合当前小规格服务器。ZIP 解压、成员数量、实际文本量、文件签名和宏会单独校验。

| 配额 | 限制 |
| --- | --- |
| 文件 | 20 MB / 份 |
| PDF | 200 页 / 份 |
| 标准正文 | 50 万字 / 份 |
| 文档与片段 | 200 份、8000 段，总计 300 万字 |
| 原文件保留 | 总计 200 MB，归档也占用 |

相同原始文件用 SHA-256 去重，重复导入返回已有记录，不重新发布归档文件，也不覆盖管理员修订。原文件作为最初导入证据保留；手动修订后的正文独立存储，页面会去掉已不适用的页码。

## 持久化、备份与部署

文档、标准正文、索引、向量缓存和原始文件 BLOB 全部在 `DATA_DIR/jasmine.sqlite`。上传原文件不进入公开静态目录，也不进入 Git。备份使用 SQLite 在线备份接口，或停止应用后复制整个数据目录；不能只复制运行中的主文件而遗漏 WAL。

部署完整 `dist`、生产依赖和私有运行配置。`dist/server/rag/parser-worker.js` 必须随主服务发布；只有前端静态文件不足以运行解析。重建索引通过后台单份资料操作完成，输入旧版本号会返回 409；日常查询不需要手工重建。

Nginx 需要对该应用配置：

```nginx
client_max_body_size 21m;
proxy_read_timeout 240s;
proxy_send_timeout 240s;
```

同样核对云代理或其他入口的请求大小、上传和响应超时。修改网关前备份配置，检查语法后再重载；不要影响原网站。SQLite、进程内并发限制和鉴权口令适用于当前单实例架构；多实例及多人分角色管理需引入集中队列、共享数据库和账户权限体系。

## 管理 API

均位于 `/api/admin/rag`，要求 `Authorization: Bearer <管理口令>`。口令不放入 URL、文档或浏览器持久存储。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/` | 资料、统计及实际解析能力 |
| POST `/documents` | multipart 单文件 `file`，可选 `title` / `source` |
| POST `/text` | JSON `{title,source,content}`，创建手写草稿 |
| GET `/documents/:id` | 文档信息、规范正文与片段 |
| GET `/documents/:id/file` | 鉴权下载最初上传的原文件 |
| PATCH `/documents/:id` | `{expectedVersion,title?,source?,status?}` |
| PUT `/documents/:id/content` | `{expectedVersion,content}`；修改已发布正文会撤回 |
| POST `/documents/:id/reindex` | `{expectedVersion}` 重建片段和索引 |
| POST `/search` | `{query,includeDraft?,documentId?,limit?}`，返回真实片段及检索模式 |

`/api/recommend` 共用一个端点，返回 `intent` 区分 `knowledge`、`catalog`、`clarify`、`recommend`、`mixed`。混合请求同时保留引用和经菜单校验的商品卡；知识、商品资料查询和澄清不清除前端已选茶单，新的推荐（含无匹配）才替换茶单。知识提问里的糖、奶、价格不是购买偏好，明确的个人过敏限制仍跨轮保留。

知识回答增加 `citations` 字段，每项包含编号、文档标识、标题、来源、页码/章节及摘录；不会提供管理下载地址或未经核验的模型来源。旧 `/api/knowledge` 仅作为兼容接口返回迁移条目的当前已发布内容，撤回同步生效，顾客页面不再预加载整份知识库。
